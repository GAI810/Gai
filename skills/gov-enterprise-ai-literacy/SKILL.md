# 政企 AI 认知课（gov-enterprise-ai-literacy）

## 何时使用

- 政企、机关、国企、事业单位要办 **AI 认知培训 / 工具串联分享会 / 半天或一天工作坊**
- 听众已经会用通用大模型，但卡在「第一步从哪开始」「现有工具怎么接到真实工作」
- 需要把多位内部嘉宾、多条能力线，串成 **一条能跟着做的工作路径**，而不是三场互不相关的产品介绍
- 需要可控的合规口径：能验证、能脱敏，不承诺没核实过的提效数字

## 核心理念：先说事，再找路

一句话：**先把工作目标或现场问题说清楚，再决定走哪条路；不要先背工具名。**

每一段演示都回答同一套问题：

1. 我现在要做什么？
2. 必须知道哪些业务信息／约束？
3. 已有能力帮我处理了哪一步？
4. 我实际拿到了什么结果？
5. 怎样验证？同事如何复现？

三条常见路径（按客户现场能力改名，别写死某一厂商）：

| 想达成什么 | 怎么进门 | 典型下一步 |
|---|---|---|
| 做成一件事 | 从目标出发 | 进「构建／编排」类平台或工作流 |
| 定位一个问题 | 从问题出发（截图／报错／异常） | 进「排查／质检」类专用 Agent 或知识检索 |
| 做出一个判断 | 目标或问题都可以 | 进「带来源的知识检索」，再人工确认 |

如果组织里已有「知识库／能力索引」，把它当成 **第一站**：补上下文，再推荐工具或资料入口。没有的话，由主持人口头做同样的分流就行。

## 开课前必须收齐

向主办方／业务方索取或一起确认：

```text
□ 受众画像：岗位、人数、是否用过 AI、是否有内部工具权限
□ 场景池：3–5 个能上台的真实工作问题（监管／政务／业务线均可；须可脱敏）
□ 可用能力清单：知识库、Agent／Skill 市场、云端开发／工作流、垂类排查工具等
  （写清：谁能用、入口、权限、当前状态＝预览／内测／正式）
□ 合规红线：敏感字段、对外口径、不能展示的系统与数据
□ 时长与形态：75 分钟分享会 / 半天工作坊 / 一天工作坊
□ 嘉宾：每人准备 1 个成熟、可复现的案例；不要求长 PPT
□ 反馈入口：会后找谁、怎么提交 Case／缺口
```

监管／政务场景示例（抽象，可替换）：

- 「窗口材料缺件，申请人反复跑」→ 做成一件事（办事指引／材料清单助手）
- 「同一事项两套口径」→ 做出一个判断（带来源的政策／规则检索）
- 「系统里看得到状态、办不下去」→ 定位一个问题（排查类 Agent + 人工确认）

## 要交付什么

| 阶段 | 交付 |
|---|---|
| 课前 | 主题与 slogan（一组即可）、议程表、嘉宾准备清单、演示题与交接模板、PPT 骨架（上屏短、串词进备注） |
| 课中 | 一条总路径图、每位嘉宾可复现的「输入 → 输出 → 验收」、会后唯一行动建议 |
| 课后 | 起步说明（入口＋权限＋最小案例）、问题反馈汇总、复盘清单（见文末） |

**短任务交接模板**（导航段交给执行段时用）：

```text
要完成的任务：
验收标准：
已确认的业务规则：
来源链接／文号／系统入口：
拟使用工具及已核实的入口、条件：
交给下一步的输入：
期望输出：
仍需确认的问题：
```

## 时长怎么切

### A. 75 分钟工具串联分享会（默认）

| 块 | 时长 | 做什么 |
|---|---:|---|
| 开场 | 5–6′ | 痛点 + 三类目标 + 总路径图 |
| 能力平台段 | 10–12′ | 「能力如何被找到／部署／复用」（实机为主） |
| 垂类工具段 | 8–10′ | 一个边界清晰的专用工具（如问题排查） |
| 导航／知识库段 | 10–12′ | 截图或问题 → 上下文 → 路径；可选同题对比（仅实测） |
| 构建平台段 | 15–18′ | 没有现成工具时，如何做出可运行结果 |
| 主持收束 | 3–6′ | 三条路径收回行动语言；一个会后动作 |
| 可选彩蛋／反常识 | 6–15′ | 日常服务入口，或「推理档位／上下文多少」对比（须有原始记录） |
| 收尾问答 | 3′ | 长问题记会后跟进 |

### B. 半天工作坊（约 3–3.5h）

在 A 的路径上加长练习：**听众自带一件真实工作 → 小组用交接模板拆题 → 在允许的沙箱里试跑 → 互评验收**。实机演示压缩，练习拉长。

### C. 一天工作坊

上午：认知框架 + 两条路径深潜。下午：第三条路径 + 合规专题 + 产出「本部门最小可试方案」并路演。

**硬约束**：每位嘉宾的时段里已含主持交接，现场不再叠长介绍和自由问答。等待／失败超过约 60 秒，切备份录屏。

## 议程怎么排（按顺序做）

### 1. 摸清听众

先回答：

- 他们卡在「不会用模型」，还是「不知道公司里已有什么」？
- 权限怎么分层：全员可看／业务线可调／仅专家可配？
- 成功标准是什么：找到入口、完成一次试跑，还是带回可复制流程？

不要用未核实的全员使用率、提效百分比做卖点。

### 2. 定目标（听众带走三样东西）

1. 一个适合自己任务的 **工具／资料入口**
2. 一种从业务资料走到 **可验证结果** 的做法
3. 一份能照着试的 **最小案例材料**

主题建议：`把现成的 AI 能力用起来` + 副题点出「真实工作」。对内可称基建串联，对外少用「基建」。

### 3. 排议程（别做成产品发布会）

- **先放业务场景，再出现工具名**
- 一页只做一件事：提问／解释关系／展示证据／交给嘉宾
- 分清「接力」还是「共同方法下的独立案例」：上一段输出能被下一段实际用上，才叫接力；否则主持人用同一套五问串起来，并说清楚「还没自动打通」
- PPT 只服务说明任务、交接与收尾；**实机是主角**

### 4. 怎么挑案例

每位嘉宾准备：

```text
分享名称：
要解决的真实问题：
为什么值得展示：
现场输入：
工具／平台实际做了什么：
现场可展示的结果：
结果如何验证：
数据边界与脱敏方式：
失败时的备选（录屏／截图）：
需要主持人如何承接：
```

优先：已有用户、短时可演示、与前后段不重复。不代嘉宾杜撰未确认的 Agent／能力名。

### 5. 练习怎么设计（工作坊必做；分享会可缩成「会后作业」）

- **输入**：听众自带的工作目标，或主办方提供的脱敏场景卡
- **过程**：用交接模板填空 → 选路径（做成／定位／判断）→ 在允许环境试跑或纸上走查
- **输出**：一页「起步说明」（入口、条件、验收、找谁反馈）
- **主持追问**（替不熟的人问）：什么时候值得先来找这个能力？开始前必须准备哪两三项？哪些步骤是工具做的、哪些仍需人判断？结果不达标时，怎样反馈最有用？

### 6. 风险与合规（必讲，且贯穿演示）

红线（上屏可极简，备注写全）：

- 敏感个人信息、未脱敏工单／截图不上屏；演示账号权限最小化
- 「有答案」≠「有依据」：必须打开来源；找不到就明说
- 代码／系统入口 ≠ 已读完代码／当前账号可调用
- 预览／测试／已上线必须分开说；未验证能力不进宣传
- 同题对比只对 **一个实测场景** 负责，不做泛化优劣结论；无核验数据不上屏（可改讲单案例）
- 不承诺固定提效比例；对比须同任务、同材料、同验收，并报告波动或标明个案
- 专用工具讲清边界：缩小范围、减少重复排查；最终业务／技术确认仍由责任人完成
- 不展示模型原始推理过程（改讲处理步骤、检索依据、调用关系）

### 7. 收尾

只留 **一个** 会后动作，例如：

> 不确定从哪里开始时，先把目标、问题描述和现场信息交给「导航入口／知识库」，再沿检索到的路径行动；有新能力或稳定业务知识，带着真实 Case 交给维护入口。

收尾页保持干净：主题句 + 资料／反馈入口。长问答会后按案例跟进。

## 演示节奏与视觉

- **封面隐喻宜单一**（如「钥匙找路」）：一个真实问题 → 导航层 → 三条路径卡片；不做机器人／宇宙／发光芯片堆砌
- 实机页只放步骤编号与备用录屏封面
- 嘉宾页：一句话定义 + 三项能力 + 交棒；不替嘉宾写操作细节
- 彩排时检查：切屏顺序、超时信号、术语是否对业务听众友好、总时长是否卡死

倒排准备（T＝培训日）：

| 节点 | 事项 |
|---|---|
| 发通知前 | 时间地点、嘉宾出席与主题确认 |
| T-5 | 每人一个成熟案例；决定接力或共同方法 |
| T-4 | 导航演示题与关键来源跑通 |
| T-3 | 实操计时、反常识素材或替代复盘 |
| T-2 | 全流程彩排 |
| T-1 | 冻结 PPT；核对入口权限；起步说明能被目标听众账号走通 |
| 当天 | 环境与备份；>60s 切录屏 |
| T+1 | 整理入口与反馈；与现场一致 |

## 课后复盘（T+1）

```text
□ 听众是否找到适合自己的入口？（自愿反馈即可）
□ 是否有人实际尝试？卡在哪一步？
□ 演示中是否出现未声明的权限／数据风险？
□ 交接是否被误解为「平台已自动打通」？
□ 哪些 Case 应补进 Index／能力清单？
□ 下一次是否缩短产品介绍、加长练习？
□ 反常识／对比页是否换成了诚实复盘？
```

效果观察用轻量自愿反馈；不把参与率或模型调用次数当作本场教学目标。

---

## 明确不做

- 把培训做成未核实数字的发布会
- 为填满时长演示未验证工具
- 把「反常识」写成预设结论，或补造 Token／耗时
- 替法务／网信做正式合规背书
- 把某一场内部工具名写死为唯一标准答案
